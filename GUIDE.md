# 🚀 Гайдбук: как поднять этого бота под себя

Этот бот — **универсальный «исходник»**: вы можете развернуть его для
своего канала, своей группы админов и своей базы данных. Всё, что нужно
прописать под себя, живёт в переменных окружения — менять код не придётся.

Ниже — пошаговая инструкция «с нуля до работающего бота». Время: ~30 минут.

---

## Что понадобится заранее

- **Аккаунт Telegram** (разумеется 🙂)
- **GitHub-аккаунт** — чтобы скопировать проект себе и подключить деплой
- **Аккаунт Render** — бесплатный хостинг, где будет жить бот
  ([render.com](https://render.com))
- **Аккаунт Neon** — бесплатная база данных PostgreSQL
  ([neon.tech](https://neon.tech)) — или любая другая PostgreSQL

---

## Шаг 1. Создайте бота в @BotFather

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, укажите имя и username (username обязательно
   заканчивается на `bot`, например `my_channel_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAH...`. Скопируйте его —
   он понадобится позже.
4. (По желанию) задайте описание и аватар бота.

## Шаг 2. Создайте группу админов

Бот пересылает предложки в группу, где модераторы решают, что публиковать.

1. Создайте в Telegram новую группу (например, «Админы канала»).
2. **Добавьте бота в группу** и назначьте его **администратором**
   (перейдите в инфо группы → «Добавить участника» → выберите бота;
   в списке участников дайте ему права администратора). Без этого Telegram
   не позволит боту читать все сообщения группы.
3. В этой группе отправьте боту `/id` — ответом он пришлёт
   `Chat ID: -100...`. Запишите это число (ваш `ADMIN_GROUP_ID`).

> Подсказка: проверить права бота можно, попросив участника написать в
> группу — предложка должна дойти до бота.

## Шаг 3. Создайте канал

Именно сюда бот будет публиковать одобренные посты.

1. Создайте канал (приватный или публичный — неважно).
2. Добавьте бота **администратором** с правом **«Публикация сообщений»**
   (инфо канала → «Администраторы» → «Добавить администратора» → бот →
   включите право публикации).
3. Узнайте ID канала: если канал публичный, проще всего через
   `@RawDataBot` — пришлите ему сообщение из канала, он покажет ID вида
   `-100...`. Припишите `-100` вручную, если его нет. Запишите это число
   (ваш `CHANNEL_ID`).

## Шаг 4. Создайте базу данных (Neon)

У бота есть вечная личная статистика и очередь — всё хранится в PostgreSQL.

1. Зарегистрируйтесь в [neon.tech](https://neon.tech) (есть бесплатный
   тариф, база не истекает).
2. Создайте новый проект → получите строку подключения вида
   `postgresql://user:pass@host/dbname?sslmode=require`.
3. Запишите её целиком (ваш `DATABASE_URL`).

> Бот сам создаст все таблицы при первом запуске — вручную ничего
> создавать не нужно.

## Шаг 5. (Опционально) Зарегистрируйте Mini App — панель модерации

Панель модерации (веб-интерфейс для админов) открывается из бота. Чтобы
она работала, нужно один раз зарегистрировать Mini App:

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newapp`,
   выберите своего бота.
2. Укажите название и описание, приложите картинку 640×360
   (анимацию можно пропустить командой `/empty`).
3. В поле адреса приложения позже укажите `https://ваш-сервис.onrender.com/app`
   (после Шага 6).
4. Придумайте короткое имя, например `panel` — это ваш
   `WEBAPP_SHORT_NAME`.

> Если не регистрировать Mini App, бот всё равно работает: просто панель
> будет доступна из личных чатов, а не из группы.

## Шаг 6. Скопируйте проект и задеплойте на Render

1. **Сделайте fork** исходного репозитория (кнопка Fork на GitHub) — так
   у вас появится ваша собственная копия, куда можно коммитить.
2. Зайдите на [render.com](https://render.com) → **New → Web Service**.
3. Подключите свой GitHub и выберите форк проекта.
4. Заполните:
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python -m bot.main`
   - **Environment** — добавьте переменные из шага ниже.
5. Нажмите **Create Web Service**. Render установит зависимости, запустит
   бота и покажет адрес вида `https://ваш-сервис.onrender.com`.


## Шаг 7. Переменные окружения (главное для «под себя»)

В **Render → Environment** добавьте:

| Переменная | Обязательна | Что вписать |
|---|---|---|
| `BOT_TOKEN` | ✅ | токен из Шага 1 |
| `ADMIN_GROUP_ID` | ✅ | ID группы админов из Шага 2 |
| `CHANNEL_ID` | ✅ | ID канала из Шага 3 |
| `DATABASE_URL` | ✅ | строка Neon из Шага 4 |
| `TIMEZONE` | — | `Europe/Moscow` (по умолчанию) |
| `WEBAPP_URL` | для панели | `https://ваш-сервис.onrender.com` |
| `WEBAPP_SHORT_NAME` | для панели | `panel` (из Шага 5) |
| `BOT_NAME` | — | название бота в панели и справке, напр. `МойКанал` |
| `PORT` | ❌ | Render задаёт сам, не трогайте |

> Тот же набор описан в файле **`.env.example`** в корне проекта.

После добавления переменных **перезапустите** сервис (Render
перезапустится сам при изменении Environment).

## Шаг 8. Проверка (чек-лист)

1. Напишите боту в личку любой текст — должна прийти приветствие, а в
   группе админов появиться пересланная предложка.
2. В группе админов нажмите **📢 Опубликовать** → выберите режим — пост
   должен уйти в канал.
3. Нажмите **🕓 Отложить** — выберите время — автору должно прийти
   уведомление «пост отложен».
4. Откройте панель: `/panel` в личке с ботом (или кнопку «Открыть
   панель») — должна загрузиться панель с вашим названием из `BOT_NAME`.

## Как запустить локально (для разработки)

1. Установите Python 3.11+ и `git`.
2. Склонируйте проект: `git clone <ваш-fork-url>`
3. `cd <папка>`
4. Создайте виртуальное окружение и поставьте зависимости:
   ```
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   source .venv/bin/activate     # Linux/macOS
   pip install -r requirements.txt
   ```
5. Скопируйте `.env.example` в `.env` и заполните значения.
6. Запустите: `python -m bot.main`

Бот поднимется локально и начнёт слушать Telegram (long polling).

## 🛠 Частые проблемы

**Бот не видит сообщения в группе.**
→ Бот не назначен администратором группы. Без прав администратора
Telegram отдаёт боту только сообщения, адресованные ему напрямую.

**Пост не публикуется в канал.**
→ Бот не администратор канала, либо у него нет права «Публикация
сообщений». Проверьте права в инфо канала.

**Ошибка подключения к базе.**
→ Неверная `DATABASE_URL`, либо база не принимает подключение. При
запуске бот проверяет соединение и пишет ошибку в лог Render (вкладка
Logs).

**Панель не открывается из группы.**
→ Mini App не зарегистрирован (Шаг 5) или `WEBAPP_SHORT_NAME` неверен.
Проще всего открывать панель из личного чата с ботом — это работает сразу.

**Не приходят уведомления автору.**
→ Обычно значит, что автор заблокировал бота. Это не ошибка: бот
продолжает публиковать, а в лог пишет, что сообщение не доставлено.
