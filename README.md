# Support Bot — бот обратной связи для Telegram

Пользователь пишет боту в личку → сообщение улетает в группу админов с пометкой,
от кого оно → админ отвечает свайпом (Reply) прямо на это сообщение → бот
отправляет ответ обратно тому пользователю.

Связки "сообщение в группе → пользователь" хранятся в SQLite (`bot.db`),
так что при перезапуске бота старые переписки не теряются и на них всё ещё
можно ответить.

## Структура проекта

```
support_bot/
├── bot/
│   ├── config.py        # чтение .env
│   ├── database.py      # SQLite: связка сообщений с пользователями
│   ├── main.py           # точка входа, запуск polling
│   └── handlers/
│       ├── common.py     # команда /id (для настройки)
│       ├── user.py       # обработка сообщений от пользователей
│       └── admin.py      # обработка ответов админов
├── requirements.txt
└── .env.example
```

## Установка

1. Установите зависимости:
   ```bash
   python3 -m venv venv
   source venv/bin/activate    # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.

3. Создайте группу в Telegram для админов, добавьте туда бота и
   **выдайте ему права администратора** (без этого он не сможет читать все
   сообщения в группе — Telegram ограничивает ботов без прав админа только
   сообщениями, адресованными им напрямую).

4. Узнайте ID этой группы:
   - Скопируйте `.env.example` в `.env`, впишите туда токен, а
     `ADMIN_GROUP_ID` пока оставьте любым числом, например `0`.
   - Запустите бота (см. ниже), напишите в группе `/id` — бот пришлёт
     правильный `Chat ID` (отрицательное число вида `-100...`).
   - Впишите этот ID в `.env` в поле `ADMIN_GROUP_ID` и перезапустите бота.

5. Итоговый `.env`:
   ```
   BOT_TOKEN=ваш_токен_от_botfather
   ADMIN_GROUP_ID=-1001234567890
   ```

## Запуск

```bash
python -m bot.main
```

## Как это работает

- **Текстовые сообщения** от юзера пересылаются в группу отдельным
  сообщением с шапкой (имя, username, ID).
- **Медиа** (фото, видео, документы, войсы, гифки) копируются через
  `copy_message`, а шапка добавляется в caption.
- **Стикеры, геолокация, контакты** и другой контент без caption —
  сначала шапка отдельным сообщением, затем сам контент. Ответить можно
  на любое из двух сообщений.
- Когда админ делает **Reply** на любое из пересланных ботом сообщений,
  бот ищет в базе, какому пользователю оно принадлежит, и копирует ответ
  админа этому пользователю через `copy_message` — так что отвечать можно
  тоже чем угодно: текстом, фото, файлом и т.д.
- Если пользователь заблокировал бота, админу придёт предупреждение об
  этом прямо в группе.

## Загрузка на GitHub

Секрет (`BOT_TOKEN`) лежит только в `.env`, а он в `.gitignore` — то есть
в репозиторий не попадёт. Никогда не убирайте `.env` из `.gitignore`.

1. Откройте терминал в папке проекта (`support_bot`).
2. Инициализируйте репозиторий и сделайте первый коммит:
   ```bash
   git init
   git add .
   git commit -m "Initial commit: support bot"
   ```
3. Проверьте, что `.env` не попал в коммит:
   ```bash
   git ls-files | grep .env
   ```
   Команда должна вывести только `.env.example`, но не `.env`. Если вывелся
   и `.env` — остановитесь, сделайте `git rm --cached .env` и закоммитьте
   заново, прежде чем пушить куда-либо.
4. Создайте новый **пустой** репозиторий на [github.com/new](https://github.com/new)
   (без автоматического README/.gitignore/license — чтобы не было конфликтов).
5. Свяжите локальный репозиторий с GitHub и запушьте (GitHub покажет эти
   команды на странице только что созданного репозитория, там же будет
   правильный URL):
   ```bash
   git remote add origin https://github.com/ВАШ_ЛОГИН/support-bot.git
   git branch -M main
   git push -u origin main
   ```
6. Откройте репозиторий на GitHub и убедитесь, что файла `.env` там нет —
   только `.env.example`.

## Деплой на Render.com

Бот работает через polling (постоянное подключение к Telegram), а не через
входящие HTTP-запросы — поэтому подходящий тип сервиса на Render это
**Background Worker**, а не Web Service. Учтите: у Background Worker на
Render нет бесплатного тарифа, минимальный план — Starter (~$7/мес). Если
это критично, есть более дешёвые/бесплатные альтернативы вроде Railway —
спросите отдельно, если понадобится сравнение.

1. Зарегистрируйтесь / войдите на [render.com](https://render.com) —
   проще всего через аккаунт GitHub, это сразу даст доступ к репозиториям.
2. В дашборде нажмите **New +** → **Background Worker**.
3. Выберите репозиторий `support-bot`, который вы запушили на GitHub
   (может понадобиться разрешить Render доступ к репозиторию/организации).
4. Заполните настройки сервиса:
   - **Name** — любое имя, например `support-bot`
   - **Region** — ближайший к вам (для Европы обычно Frankfurt)
   - **Branch** — `main`
   - **Root Directory** — оставьте пустым, если репозиторий = папка `support_bot`
   - **Runtime** — `Python 3`
   - **Build Command** — `pip install -r requirements.txt`
   - **Start Command** — `python -m bot.main`
   - **Instance Type** — Starter
5. В разделе **Environment Variables** (или на этапе создания в блоке
   "Advanced") добавьте два секрета — те же значения, что у вас в `.env`:
   - `BOT_TOKEN`
   - `ADMIN_GROUP_ID`
6. Нажмите **Create Background Worker** — начнётся сборка и запуск.
7. Откройте вкладку **Logs** и убедитесь, что видите строку вида
   `Бот запущен, начинаю polling...` без ошибок.
8. Напишите боту в Telegram — сообщение должно прийти в группу.

### Про хранение данных на Render

Файловая система на Render — не постоянная: при каждом передеплое/рестарте
`bot.db` пересоздаётся с нуля, и старые связки "сообщение → пользователь"
теряются (админы не смогут ответить на переписки, которые велись до
рестарта; новые сообщения продолжат работать как обычно). Если нужна
устойчивая история между деплоями — подключите Persistent Disk в настройках
сервиса (доступно на платных планах) и укажите путь к диску как `DB_PATH`.

### Разовая рекомендация по безопасности

Токен бота был напечатан в этом чате в открытом виде, так что технически
он уже "засветился". Это не критично, но если хотите перестраховаться —
после того как всё заработает, зайдите к [@BotFather](https://t.me/BotFather),
выберите бота → **API Token** → **Revoke current token**, и обновите новое
значение в `.env` и в Environment Variables на Render.

## Деплой на Render (бесплатный вариант)

Бот работает через long polling — это постоянный процесс без своего
веб-адреса. Чтобы Render бесплатно держал его "живым" (тип Web Service),
в проект добавлена крошечная HTTP-заглушка (`start_web_server` в
`bot/main.py`), которая отвечает "Bot is running" на любой запрос.
Render проверяет, что сервис слушает порт — иначе считает деплой неудачным.

Так как free Web Service на Render засыпает после 15 минут без запросов,
дополнительно нужен внешний "будильник" — бесплатный сервис вроде
[cron-job.org](https://cron-job.org), который будет дёргать адрес бота
каждые несколько минут.

Настройки для сервиса на Render:

- **Type**: Web Service
- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `python -m bot.main`
- **Environment Variables**: `BOT_TOKEN`, `ADMIN_GROUP_ID` (переменную
  `PORT` Render подставляет сама, вручную задавать не нужно)

## Возможные доработки

- Разграничение прав админов (например, только участники с ролью
  Administrator/Creator могут отвечать).
- История переписки / просмотр диалога с конкретным юзером.
- Форум-топики в супергруппе — по топику на каждого пользователя вместо
  плоской ленты.
- Бан/игнор-лист для спамеров.
- Деплой как systemd-сервис или в Docker для постоянной работы.
