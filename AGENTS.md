# Правила работы с проектом tg-AniDRIP_bot (публичный исходник)

> 🌐 Это **публичный репозиторий-исходник для всех желающих**. Не путать
> с личным рабочим репозиторием `Kaster9452/tg-anidrip2` — домашним ботом
> владельца со своими настройками.

## 1. Стек — только Python

Бот на aiogram 3 + aiohttp + asyncpg + чистый HTML/CSS/JS для мини-приложения
(`bot/static/index.html`). Никогда не добавляй Node.js, TypeScript,
`package.json`, `server.ts` и не предлагай «переписать на …» — даже если это
кажется технически лучше. Это не входит в задачу.

## 2. Не удаляй файлы пачками

Если для выполнения задачи кажется, что нужно удалить `webapp.py`,
`callbacks.py`, тесты и т.п. — это признак того, что ты меняешь архитектуру,
а не делаешь точечную правку. Остановись и спроси хозяина, прежде чем
удалять что-либо, кроме файла, который сам создал в этой же задаче.

## 3. Одна задача — минимальный диф

Меняй только то, что попросил пользователь. Если задача — «сделай альбомы
в /mypost», правка должна коснуться 1-2 файлов
(`bot/handlers/ownpost.py`, максимум `bot/database.py`), а не половины
репозитория.

## 4. Миграции базы данных

Только через `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` внутри `SCHEMA_SQL`
в `bot/database.py`. Таблицы уже существуют в проде — никогда не пересоздавай
их и не меняй существующие колонки.

## 5. Перед тем как сказать «готово»

Обязательно прогони:

```
python -m compileall -q bot tests
python -m unittest discover -s tests -v
```

Если тесты не проходят — задача не закончена.

## 6. Git — только точечные коммиты

Не используй `git push --force`, не меняй remote, не переписывай историю.
Если что-то пошло не так — спроси, прежде чем исправлять через силовые
команды.

## 7. Пользователь не программист

Объясняй план и последствия простыми словами. Если не уверен в масштабе
изменений — сначала опиши план и спроси подтверждение, а не делай
«на всякий случай по-крупному».

## 8. Не трогай деплой без необходимости

Не меняй Render / переменные окружения (`BOT_TOKEN`, Build Command,
Start Command и т.п.), если задача явно не про деплой.

## 9. Два репозитория — разные судьбы

У проекта два репозитория в организации `Kaster9452`, и это разные вещи:

- `Kaster9452/tg-AniDRIP_bot` (этот) — **публичный исходник для всех**.
  Универсальная «заготовка под себя»: GUIDE.md, .env.example,
  параметризация через переменные окружения. Можно форкать и
  разворачивать где угодно, он не привязан к личным настройкам.
- `Kaster9452/tg-anidrip2` — **личный работающий проект владельца**. Живёт
  со своими настройками и деплоем, без «обобщений под всех» (без GUIDE.md
  и общих «под себя» изменений).

Никогда не переноси изменения между этими репозиториями и не пуши в оба
одновременно, если не было явной просьбы. В частности: не тащи
«универсальные» правки (параметризация, гайды) в личный репозиторий и не
тащи личные настройки в исходник.

## 10. Эти правила — только для кода бота; вне кода — свобода агента

Правила 1–9 обязательны только для **рабочего кода бота**: `bot/`, `tests/`,
`requirements.txt`, схемы БД и настроек деплоя. Всё, что за пределами рабочего
кода — README, GUIDE и другая документация, скриншоты, картинки, презентации,
оформление репозитория, разовые вспомогательные скрипты — агент делает
**самостоятельно и без согласования**:

- можно свободно создавать, править и удалять такие файлы по своему усмотрению,
  включая старые скриншоты и временный мусор из прошлых задач (правило 2
  «спросить перед удалением» на них не распространяется);
- можно ставить любые локальные инструменты для разовых задач (Pillow, Node
  и т.п.) и писать временные скрипты на чём удобно — главное, чтобы они не
  становились зависимостью бота и не попадали в `requirements.txt`;
- подход, структуру и оформление агент выбирает сам, у хозяина не спрашивая.

Неприкосновенными остаются только рабочий код бота, тесты, схема БД, настройки
деплоя (правило 8) и правило 9 про два репозитория.
